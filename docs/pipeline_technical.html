GenoDisc Pipeline - Technical Details

This document describes the methods and tools used by the GenoDisc pipeline. For instructions on how to install and run the pipeline, see the User Guide.

Workflow overview

The pipeline is implemented as a Snakemake workflow composed of eight rule modules:

  1. dependencies.smk - Downloads and prepares reference data (1000 Genomes, gene annotations, LD scores, TWAS weights, drug-gene databases)
  2. sumstat_qc.smk - Cleans, harmonises, and quality-controls GWAS summary statistics
  3. finemapping.smk - Performs fine-mapping of GWAS loci
  4. magma.smk - Runs gene-level and gene set association analyses
  5. twas_pwas.smk - Performs transcriptome- and proteome-wide association analyses
  6. smr.smk - Runs summary-data-based Mendelian randomisation
  7. gcsc.smk - Performs gene co-regulation-based drug scoring
  8. report.smk - Packages all results into a single .rds object

Reference data and tool dependencies are downloaded automatically on the first pipeline run.

Part 1: Descriptive analyses

Summary statistic QC

GWAS summary statistics undergo a standardised cleaning procedure implemented in scripts/sumstat_cleaner.R:

  1. Column name mapping: The pipeline recognises a wide range of common column name variants and maps them to a standardised set of column names. For example, PVALUE, PVAL, P_VALUE, and GC_PVALUE are all mapped to P.

  2. Allele harmonisation: Alleles are harmonised against the 1000 Genomes reference panel. Strand-ambiguous variants are checked against reference allele frequencies and removed if they cannot be resolved.

  3. Genome build detection and liftover: If the summary statistics do not match the GRCh37/hg19 build, the pipeline attempts automatic coordinate liftover using the UCSC liftOver tool.

  4. Quality filtering: Variants are filtered based on:

    • Allele frequency (if available): extreme frequency variants are flagged
    • Imputation quality (INFO score, if available)
    • Duplicate removal
    • Multiallelic variant removal

  5. Effect size conversion: If only odds ratios are provided, they are converted to log-odds (BETA). Z-scores are converted to BETA and SE where possible.

The cleaned summary statistics are stored in {outdir}/results/{gwas}/gwas_sumstat/.

  • A2: A2, ALLELE2, OTHER_ALLELE, NEA, ALT, NON_EFFECT_ALLELE, HM_OTHER_ALLELE, …
  • BETA: BETA, EFFECT, B, SIGNED_SUMSTAT, EST, LOG_ODDS, HM_BETA, …
  • OR: OR, ODDS_RATIO, ODDS-RATIO, OR(A1), HM_ODDS_RATIO, …
  • SE: SE, STDERR, STDER, STANDARD_ERROR, OR_SE, …
  • P: P, PVALUE, PVAL, P_VALUE, P-VALUE, WALD_P, P_BOLT_LMM, …

LD score regression

LDSC (LD Score Regression) is used to estimate:

  • SNP-heritability (\(h^2_{SNP}\)): the proportion of phenotypic variance explained by common SNPs
  • LD score regression intercept: an indicator of confounding or population stratification in the GWAS

The pipeline uses pre-computed LD scores from the European 1000 Genomes reference panel. Summary statistics are first munged using the LDSC munge_sumstats.py script to ensure compatibility.

Results are stored in {outdir}/results/{gwas}/ldsc/.

LD clumping

LD clumping is performed using PLINK to identify independent genome-wide significant associations. The procedure uses:

  • P-value threshold: 5 x 10-8
  • LD threshold (\(r^2\)): 0.1
  • Clumping window: 250 kb
  • Reference panel: 1000 Genomes European samples

Results are stored in {outdir}/results/{gwas}/clump/.

GCTA-COJO

GCTA-COJO (Conditional and Joint analysis) performs stepwise conditional analysis to identify independently associated variants. Unlike simple LD clumping, COJO accounts for the joint effects of variants using summary statistics and an LD reference panel.

Results are stored in {outdir}/results/{gwas}/cojo/.

Part 2: Gene finding analyses

Fine-mapping (SuSiE)

SuSiE (Sum of Single Effects) is used for Bayesian fine-mapping. For each genome-wide significant locus, SuSiE identifies credible sets of causal variants. The analysis:

  1. Defines loci around genome-wide significant variants
  2. Computes LD matrices from the 1000 Genomes European reference panel
  3. Fits the SuSiE model allowing for up to L=1 causal variants per locus (configurable)
  4. Returns 95% credible sets with posterior inclusion probabilities (PIPs) for each variant

Results are stored in {outdir}/results/{gwas}/finemap/.

MAGMA gene-level association

MAGMA performs gene-level association analysis by aggregating SNP-level association statistics within gene boundaries. The pipeline:

  1. Maps SNPs to genes using Ensembl gene annotations (with a configurable window)
  2. Computes gene-level test statistics accounting for LD between SNPs
  3. Provides gene-level p-values and effect sizes

Results are stored in {outdir}/results/{gwas}/magma/.

Transcriptome-wide association (TWAS)

FUSION performs transcriptome-wide association studies by testing whether genetically predicted gene expression is associated with the GWAS phenotype. The pipeline supports multiple eQTL reference panels:

  • GTEx panels: Tissue-specific eQTL weights from the GTEx consortium (user-specified tissues)
  • PsychENCODE: Brain-specific eQTL weights from the PsychENCODE consortium
  • Non-GTEx panels: Additional eQTL panels (e.g. CMC brain RNA-seq)
  • External panels: User-provided TWAS weight panels in FUSION format

For each panel, the pipeline:

  1. Runs TWAS per chromosome
  2. Combines results across chromosomes
  3. Identifies genome-wide significant gene-trait associations (Bonferroni-corrected)
  4. Performs conditional analysis on significant hits to identify independently associated genes

Results are stored in {outdir}/results/{gwas}/twas/.

Summary-data-based Mendelian randomisation (SMR)

SMR tests for causal or pleiotropic associations between gene expression and complex traits using summary-level data from GWAS and eQTL studies. The pipeline supports multiple eQTL/pQTL reference panels:

  • PsychENCODE: Brain eQTL data
  • MetaBrain: eQTL data from multiple brain regions (cortex, basal ganglia, cerebellum, hippocampus, spinal cord)
  • eQTLGen: Blood eQTL data
  • ROSMAP: Brain pQTL data

The HEIDI (Heterogeneity in Dependent Instruments) test is used to distinguish causal/pleiotropic associations from linkage.

Results are stored in {outdir}/results/{gwas}/smr/.

Proteome-wide association (PWAS)

PWAS extends the TWAS framework to protein levels, using pQTL weights to predict genetically determined protein expression. The pipeline supports:

  • ROSMAP: Brain pQTL weights (n=376)
  • Banner: Brain pQTL weights (n=152)

PWAS uses the same FUSION framework as TWAS, with protein expression prediction models in place of gene expression models.

Results are stored in {outdir}/results/{gwas}/pwas/.

Part 3: Drug finding analyses

MAGMA DrugTargetor enrichment

MAGMA gene set enrichment analysis is performed using DrugTargetor drug-gene interaction sets. This tests whether genes targeted by specific drugs are enriched for GWAS associations. The analysis also evaluates enrichment at the ATC (Anatomical Therapeutic Chemical) classification level.

Results are stored in {outdir}/results/{gwas}/magma/.

TWAS-GSEA DrugTargetor enrichment

TWAS-GSEA performs gene set enrichment analysis using TWAS results rather than SNP-level summary statistics. By leveraging gene expression prediction, TWAS-GSEA can detect drug-gene set enrichments that are not captured by traditional MAGMA-based approaches.

Both directional and non-directional enrichment tests are available:

  • Directional: Tests whether disease-associated genes have expression changes in the same direction as drug effects
  • Non-directional: Tests for enrichment regardless of effect direction

Results are aggregated across TWAS panels and stored alongside other enrichment results.

TWAS-GSEA CMAP drug signatures

In addition to DrugTargetor gene sets, TWAS-GSEA is also applied using reprocessed CMAP (Connectivity Map) level 5 drug expression signatures. This identifies drugs that reverse the disease-associated gene expression pattern, which is a key strategy in computational drug repurposing.

The CMAP analysis tests each drug’s expression signature against the TWAS results to identify compounds whose effects on gene expression oppose the disease-associated pattern. Results include enrichment statistics and drug annotations including mechanism of action (MOA).

Gene co-regulation scoring (GCSC)

GCSC (Gene Co-regulation-based Scoring) uses tissue-specific gene co-regulation networks from GTEx to score drug-gene interactions. Rather than testing individual gene associations, GCSC evaluates whether the co-regulation structure of drug target genes is associated with the GWAS phenotype.

The analysis:

  1. Runs TWAS using GTEx v7 weights for specified tissues
  2. Prepares drug-gene interaction sets from DrugTargetor
  3. Computes co-regulation-based enrichment scores for each drug

Results include drug-level scores and ATC classification enrichment, stored in {outdir}/results/{gwas}/gcsc/.

MAGMA tissue enrichment

MAGMA tissue enrichment analysis tests whether genes expressed in specific tissues are enriched for GWAS associations. This uses GTEx tissue expression profiles to identify tissues where GWAS-associated genes are preferentially expressed, and performs conditional analysis to identify independently enriched tissues.

Results are stored in {outdir}/results/{gwas}/magma/.

Results packaging

The package_results rule (rules/report.smk) aggregates all analysis results into a single R list object saved as results_package.rds. This file is the primary output for downstream analysis and visualisation.

The results package contains nested lists structured by GWAS and analysis type, and can be loaded directly into R or explored using the bundled Shiny application.
